# 独立制作人 · v2 玩法设计与修改计划

> **v2 主题：时间压力下的资源博弈**
> 把 v1「无限回合、资源归零即败」的模型，重构为「48 周硬时限、必须完成、质量决定销量」的限时经营博弈。
> 配套实现：`index.html`（单文件，事件库 `EVENTS` + 顶部常量 + 游戏逻辑函数）。

---

## 0. v1 → v2 变更摘要

| 维度 | v1 | v2 | 说明 |
|---|---|---|---|
| 时间 | 无上限，抽到哪算哪 | **4 季度 × 12 周 = 48 回合硬上限** | 新增「周」概念，时间成为稀缺资源 |
| 胜利 | `pr ≥ 100` 即胜 | `pr ≥ 100` 且 **必须在 48 周内** | 超时未完成 = 跳票烂尾（失败） |
| 质量 qu | 归零/爆表都导致失败 | **归零/爆表仍失败（恢复 v1）**，并新增：通关后决定销量/评级 | qu 既是「生死线」又是「评分线」 |
| 失败条件 | mo/fu/qu/sc 任一项 ≤0 或 ≥100 | mo/fu/qu/sc ≤0 或 ≥100（qu 恢复致命）＋**超时** | 失败来源为「崩盘（含 qu）」与「超时」 |
| 事件选项语义 | L 进取 / R 保守（对称 ±d） | **A=−资源+进度（赶工）；B=+资源（养兵）** | 明确围绕「耗资源换进度」做博弈 |
| 结算 | 胜/负两态 | 完成 → **S/A/B/C 评级 + 销量 + 用时** | 质量与速度共同决定成绩 |
| 核心体验 | 熬过随机资源波动 | **在有限 48 周内，把燃料与质量都稳住、换算成进度且不崩盘** | 博弈点从「别归零」变为「别超时、别崩盘、还保成色」 |

## 1. 核心玩法总览

### 1.1 时间轴（周 / 季度 / 轮）

```
1 轮（一局游戏）
 = 4 季度
 = 48 周（= 48 个回合）
每回合（每周）：抽取 1 张事件卡 → 二选一 → 资源与进度结算
```

- 自变量统一用 **`week`（1…48）**，不再用「季度」作为进度自变量（季度仅用于展示与叙事节奏）。
- 季度 = `ceil(week / 12)`，第 1 季度=周 1–12，第 4 季度=周 37–48。
- 第 48 周结束若 `pr < 100` → **超时失败**。

### 1.2 资源与胜负

| 资源 | 角色 | 上限/下限 | 失败关联 |
|---|---|---|---|
| **进度 pr** | 唯一胜利指标，必须到 100 | 0 → 100 | `pr≥100` 胜；48 周未到 = 超时败 |
| **士气 mo / 资金 fu / 排期 sc** | 「燃料」——推进进度的代价 | ≤0 或 ≥100 → **崩盘失败** | 是失败条件（建议爆表也失败，避免无脑堆叠） |
| **质量 qu** | 「生死线」+「评分燃料」——归零/爆表失败，且通关后决定销量/评级 | 0 → 100，**≤0 或 ≥100 → 崩盘失败（与 v1 一致）** | 失败条件之一；`pr=100` 时换算成销量 → 评级 |

> 设计意图：进度是「目的地」，燃料（mo/fu/sc）是「油」，质量（qu）既是「成色」也是「另一条生死线」。
> 你既要烧油赶路（否则超时），又不能把油烧干（否则崩盘），还得保住质量——质量一旦归零立即崩盘，而保得越高通关评分越好。

### 1.3 核心博弈点（对应需求 #4）

**有限 48 周内必须完成，因此「消耗资源赶进度」是唯一出路，但消耗有代价。**

- 若每回合都选 A（−资源 +进度）：进度涨得快，但燃料迅速见底 → **崩盘失败**。
- 若每回合都选 B（+资源）：燃料健康，但进度涨太慢 → **48 周超时失败**。
- 最优解：**交替**——燃料充足时烧油赶工（A），燃料吃紧时养兵回血（B），并在第 ~40–45 周前后把进度推满，同时尽量保住质量。

质量在此模型里天然成为风险/收益旋钮：赶工（A）常常**顺带扣质量**，养兵（B）常常**顺带补质量**。于是「赶进度」与「保评分」直接冲突，且质量还有一条独立的生死线（归零即崩盘）——这正是 v2 想凸显的张力：你必须在 48 周内、在燃料与质量都不崩的前提下，把进度推满并尽量保住成色。

## 2. 事件数值设计原则（对应需求 #5）

每个事件两个选项，严格落在两种定位之间：

```
选项 A（进取 / 赶工）：  f = { pr: +Δp, 某燃料: −Δr,  (qu: −Δq) }
选项 B（稳健 / 养兵）：  f = { pr: +0~+Δp', 某燃料: +Δr,  (qu: +Δq') }
```

- **A 必须有正进度、且吃掉资源**（资源可能 1 项或 2 项）；A 可附带 `qu: −`（赶工降质）。
- **B 必须回补资源**（与 A 吃的同一/另一项燃料对称 ±Δr，保证随机选期望≈0），B 进度很少或为零；B 可附带 `qu: +`（精修提质）。
- 随机选（50/50）时，单项燃料的净变化期望 ≈ 0（对称），进度净变化 > 0（因为 A 的 pr 增益 > B 的 pr 增益），从而游戏既「能推进」又「靠方差制造崩盘/超时风险」。

> 与 v1 生成器的关系：v1 已是「L 高 pr 伤主资源 / R 低 pr 补主资源」的对称结构，v2 只需
> (1) 把 pr 增益量级下调到与「48 周」匹配；(2) 显式把 qu 接到 A 的代价 / B 的收益上；(3) 重新蒙特卡洛标定。

## 3. 数值模型与标定值（初版，需蒙特卡洛校准）

### 3.1 进度预算

```
需要总进度 = 100
可用回合 = 48
理论最低周均进度 = 100 / 48 ≈ 2.08
```
由于 B 周几乎不涨进度，实际 A 周需承担更多。建议初值（待校准）：

| 项 | A（赶工）pr 增益 | B（养兵）pr 增益 |
|---|---|---|
| 初值范围 | **+4 ~ +6** | **0 ~ +2** |

这样「约 60% A + 40% B」的混合可在 ~40–45 周内达标，留有余量；纯 B 必然超时。

### 3.2 燃料（mo/fu/sc）

| 参数 | 初值建议 | 说明 |
|---|---|---|
| 初始值 INIT | mo/fu/sc = **50**，qu = **30–50** | 居中，离 0/100 都有缓冲；qu 起始略低，鼓励养质 |
| A 单项燃料代价 Δr | **−6 ~ −10** | 激进周的真实成本 |
| B 单项燃料回补 Δr | **+6 ~ +10**（与 A 对称） | 保证随机期望≈0 |
| 每事件影响燃料项数 | 1（主）或 1+1（副，50% 概率） | 同 v1 |

### 3.3 质量 qu 耦合（既是失败线也是评分线）

- A 附带 `qu: −3 ~ −6`（赶工降质，约 50% 的 A 事件带）——注意别把 qu 扣到 0
- B 附带 `qu: +3 ~ +6`（精修提质，约 50% 的 B 事件带）
- qu 恢复为致命资源（≤0 或 ≥100 崩盘，与 v1 一致），**同时**在 `pr=100` 通关时换算成销量 → 评级（见 §4）

### 3.4 校准目标（建议，可议）

用蒙特卡洛（洗牌抽 500 事件、随机/策略选边、跑 N 局）标定 `Δr` 与 pr 范围，使：

| 玩家类型 | 目标结果 |
|---|---|
| **随机乱玩**（50/50） | 通关率 ≈ **40%–50%**（qu 恢复致命后失败来源增多，见 §8） |
| **合理交替**（燃料<阈值切 B，否则 A） | 通关率 ≈ **85%+**，且平均 qu ≥ 65（拿 A 评级） |

> 校准方法复用 v1 脚本（`/tmp/gen_events.py` 思路）：二分搜索基准 `base_d` 调方差；新增「周上限 48 + 超时判负」的模拟分支；分别统计随机/策略策略通关率。
> 注意：v1 的「80% 随机通关」目标在新硬时限下**不再适用**，应下调（见 §8 待确认）。

## 4. 结算与评级（对应需求 #1）

`pr` 在第 ≤48 周达到 100 → 进入结算，不再区分「胜利/失败」两态，而是给**成绩**：

### 4.1 销量（由质量决定）

```
销量 units = round( (qu / 100) × SALES_MAX )      // SALES_MAX 建议 1,000,000
```
可选对数/凹函数让低质量不至于归零、高质量边际递减；v2 先用线性，后续调。

### 4.2 评级

| 评级 | 条件（初版） |
|---|---|
| **S** | qu ≥ 80 且 weeksUsed ≤ 44 |
| **A** | qu ≥ 65 |
| **B** | qu ≥ 45 |
| **C** | qu < 45 |
| **失败（无评级）** | 崩盘（燃料归零/爆表）或 超时（48 周 pr<100） |

> 速度奖励：用更少周完成可上探更高评级（S 需 ≤44 周），鼓励「卡着燃料安全线快速通关」。
> 可选附加分：剩余资金 fu 作为「利润」计入成绩展示（不影响评级门槛）。

### 4.3 结算页展示

- 评级徽章（S/A/B/C 或「项目失败」）
- 销量数字（带动效）
- 用时：第 X 周 / 共 48 周
- 四项资源终值 + 质量

## 6. UI / UX 改动

1. **时间可视化（核心，必做）**：新增「时间」维度展示——建议 header 下方放一条 **48 格周刻度时间轴**（已用周数高亮、剩余灰），让「限时」肉眼可见，强化博弈压力。可复用 `.prog .ticks` 的思路做 48 段刻度。
2. **季度/周徽章**：把现有 `quarter-badge` 文案改为「第 Q 季度 · 第 W 周」或「第 W / 48 周」；保留脉冲绿点表示「进行中」。
3. **资源卡语义更新**：
   - 质量卡：移除「归零/爆表=危险」的红字危机语义，改为标注「质量 → 销量 / 评级」的提示（如副标题「决定销量」）。
   - 士气/资金/排期卡：保留危机红字（仍会崩盘）。
4. **事件卡**：左右选项已能显示 pr 增减（mid-stats 含「进度」行），保持；可考虑在「赶工」侧加一个 🔥/「赶工」角标、「养兵」侧加「回血」角标（用现有贴纸风格，非 emoji）。
5. **结算 overlay**：从「PROJECT SHIPPED / FAILED」二态，改为评级大徽章 + 销量 + 用时 + 终值面板（沿用现有 `.modal/.statline` 结构扩展）。

## 8. 待确认问题（需你拍板）

1. **质量爆表（≥100）是否仍失败？** 归零失败已恢复 v1 行为；爆表失败（v1 的「完美主义陷阱」）是否也一并恢复？建议恢复，维持原行为。
2. **超时是否即失败？** 需求说「必须完成」，故 48 周 pr<100 = 失败（跳票）。确认？
3. **评级是否影响「是否算赢」？** 建议：完成（pr 满）= 赢，评级只是成绩；还是要求至少 C 才算赢？
4. **销量/评级是否仅展示（单轮）？** 还是用于解锁/累计？v2 建议仅当局展示。
5. **随机玩通关率目标定多少？** v1 是 80%；v2 加了硬时限且 qu 恢复致命，失败来源更多，建议随机通关率目标下调至 ~40%–50%（更硬核）。是否接受？
6. **起始质量 qu 初值？** 建议 30–50（偏低，鼓励养质）；或 50 居中。
7. **时间轴 UI 形式？** 48 格刻度条 vs 简洁「第 W/48 周」数字，二选一或并用于不同屏幕。

> 以上确认后，按 §7 实施。本文件即 v2 的设计基线，实施时同步更新此表与数值。
